Social media scheduling with Claude

Say what goes where and when. Approve it. Done.

Give Signalpost your reels, carousels and photos, and say in plain words which network each one goes to and when. Claude writes a native post for every network in your brand's voice, Signalpost checks each one against that network's rules, and nothing is scheduled until you approve it in a pull request. Then it goes to Upload-Post and onto your content calendar.

How it works

Four steps, one approval

01 · Plan

Say it in plain words

Drop media in media/ and write plan.md: what goes where, and when. Any language, any time zone.

02 · Write

Claude writes per network

Reads the plan into posts, then writes each network's version in your voice from brand.md: hooks, titles, hashtags, first comments.

03 · Check

Every rule, every post

Lengths, hashtags, titles, formats, video length and shape, links, daily caps. A broken rule gets one rewrite; what's still broken is blocked.

04 · Approve

Merge to schedule

Drafts arrive as a pull request you can edit. Merging schedules them with Upload-Post and updates the calendar. Delete a draft later to cancel it.

The rules it checks

Every network, its own rules

From each network's help pages and Upload-Post's API docs, checked November 2026. They live in rules/networks.json, so when a network changes a limit you edit one line. Blocked stops a post; warning lets it through and tells you.

Rule of thumb: if anyone else approves posts (a client, a manager), use GitHub. The pull request is the approval trail.

Option A: GitHub recommended

  1. Click Use this template and make a private copy. Your plans and unreleased media stay private.
  2. Connect your accounts in Upload-Post under one profile.
  3. Add secrets ANTHROPIC_API_KEY and UPLOADPOST_API_KEY, variables UPLOADPOST_PROFILE and SIGNALPOST_ENABLED=true.
  4. Allow Actions to create pull requests (Settings → Actions → General).
  5. Fill in brand.md, add media, write plan.md. A pull request appears a minute later.

Option B: your computer

  1. Install Node.js 20+. There's nothing else to install.
  2. Copy .env.example to .env and add your keys.
  3. Write plan.md, then run the steps:
npm run draft      # Claude writes drafts/
npm run check      # after you edit them
npm run schedule   # sends approved posts to Upload-Post

Design decisions

Built so nothing goes out by surprise

Your merge is the only "go"

Drafting never schedules. Only a merge to main (or your own edit on main) does, and every post gets a fixed time: Signalpost never posts "now" and never uses a queue.

Pasted text is never an instruction

Lines starting with > are notes from others. No post can come from them, and text that tries to instruct the AI is flagged. The demo's publisher email asks to post a giveaway link everywhere; it's ignored and shown to you.

Only your links

A link that isn't listed in brand.md blocks the post, so a bad link can't slip into a caption. Links are also taken out of X posts, because Upload-Post strips them there.

Every post quotes your plan

Each post must quote the line of your plan it came from, word for word, or it's dropped. Media must exist, networks must be yours, and the time must be real and in the future.

Guesses are questions

When Claude had to pick a day or time ("this weekend"), the draft is marked needs your answer and isn't scheduled until you say so. REVIEW_MODE does that for every post.

Edit, delete, cancel

Edit a draft and only that post is rescheduled. Delete it and the scheduled job is cancelled. Each request has an idempotency key, so a retry can never post twice.

Limits before they bite

Daily caps per network, the free plan's 10 uploads a month and its missing TikTok are checked before anything is sent, so you see the problem in the pull request instead of a failed post.

Quiet logs

Run logs show counts only, never what your posts say, because logs of public repositories are visible to anyone. DRY_RUN does everything but call Upload-Post.
